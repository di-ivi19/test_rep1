## 🚀 Начало работы

Рекомендуемый способ запуска ha-mcp — **Custom Component HA-MCP**. Он устанавливается в Home Assistant через HACS, запускает полный сервер **в том же процессе (in-process)** и работает на **любых** типах установки Home Assistant — Home Assistant OS, Supervised, Container и Core — с полной функциональной эквивалентностью. Это самый простой вариант установки в любом случае: не нужно управлять токенами доступа.

**Добавьте его в Home Assistant через HACS (предпочтительный способ установки):**

[![Добавить HA-MCP в HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=homeassistant-ai&repository=ha-mcp-integration&category=integration)

**Быстрый старт:**

1. Установите **Custom Component HA-MCP** из HACS — нажмите на бейдж выше, либо в HACS откройте **Интеграции → ⋮ → Пользовательские репозитории**, добавьте `https://github.com/homeassistant-ai/ha-mcp-integration` (категория: **Интеграция**), затем нажмите **Загрузить**.
2. **Перезапустите Home Assistant.**
3. Перейдите в **Настройки → Устройства и службы → Добавить интеграцию**, найдите **HA-MCP Custom Component**, выберите **HA-MCP Server** и нажмите **Отправить**. Создание записи запускает сервер.
4. Скопируйте URL подключения с экрана **Настроить** («Settings → Devices & Services → HA-MCP Custom Component → HA-MCP Server → Configure») — он также выводится в журнале Home Assistant. Уведомление подтвердит, что сервер запущен, и укажет на нужное место.
5. Вставьте этот URL в свой ИИ-клиент — готово.

**URL подключения.** На экране «Configure» вы получаете webhook-URL Home Assistant для удалённых клиентов — `https://<your-ha-domain>/api/webhook/<webhook-id>` через Nabu Casa или любой обратный прокси, уже направленный на Home Assistant (локально: `http://<ha-host>:8123/api/webhook/<webhook-id>`). Для клиентов в той же сети сервер также доступен напрямую по адресу `http://<ha-ip>:9584/private_<random>`.

- **Заменяет другие способы установки:** сервер в процессе — это полноценная автономная установка ha-mcp — он заменяет приложение (аддон), Docker и методы uvx/PyPI (stdio). Запускайте только один вариант; не запускайте внутрипроцессный сервер вместе с другой установкой.
- **Только локально?** Отключите опцию **Remote access via webhook** в параметрах записи — webhook вообще не регистрируется, при этом прямой порт и боковая панель продолжают работать.
- **Панель настроек:** пока сервер работает, в боковой панели Home Assistant появляется панель **HA-MCP** (только для администраторов) для управления инструментами, флагами функций, резервными копиями и темами.
- **Необязательная аутентификация:** установите **Webhook authentication** в значение `ha_auth`, чтобы требовать вход в учётную запись Home Assistant вместо использования секретного URL в качестве учётных данных.
- **Ручная установка (без HACS):** скопируйте `custom_components/ha_mcp_tools/` из этого репозитория в каталог `config/custom_components/` вашего Home Assistant, затем перезапустите и добавьте интеграцию, как описано выше.

Второй тип записи компонента, **запись сервисов файлов и YAML** (**HA-MCP File & YAML Tools**), нужен только в том случае, если вы включаете опциональные инструменты редактирования файлов и YAML ha-mcp (флаги функций, по умолчанию выключены) — в остальных случаях пропустите его; его можно добавить позже в любой момент. Он работает с любым типом сервера (in-process, приложение, Docker или stdio).

[Полная документация по серверу в процессе →](docs/in-process-server.md) · [Мастер настройки для клиентских конфигураций →](https://homeassistant-ai.github.io/ha-mcp/setup/)

### 🏠 Приложение Home Assistant (аддон)

Предпочитаете запускать ha-mcp как **приложение (аддон)** Home Assistant? На установках **Home Assistant OS** и **Supervised** это хороший второй вариант — не нужно управлять токенами доступа, и он работает с Claude Desktop, Claude.ai, ChatGPT и любым другим MCP-клиентом в вашей локальной сети или настроенным на удалённый доступ.

1. Добавьте репозиторий в ваш экземпляр Home Assistant:

   [![Добавить репозиторий](https://my.home-assistant.io/badges/supervisor_add_addon_repository.svg)](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2Fhomeassistant-ai%2Fha-mcp)

   Если при этом открывается Магазин приложений без диалога добавления репозитория ([известная проблема Home Assistant](https://github.com/home-assistant/my.home-assistant.io/issues/698)), добавьте его вручную: **Настройки → Приложения → Установить приложение → ⋮ → Репозитории**, затем вставьте `https://github.com/homeassistant-ai/ha-mcp`.

2. Установите **"Home Assistant MCP Server"** из раздела **Настройки → Приложения → Установить приложение** и нажмите **Запустить**. *(Home Assistant 2026.2 переименовал "Аддоны" в "Приложения"; в старых версиях это Магазин аддонов.)*
3. Откройте вкладку **Журналы**, чтобы найти ваш уникальный MCP URL.
4. Подключите ваш ИИ-клиент к этому URL — **настройка токена или учётных данных не требуется**.

[Полная документация по приложению →](homeassistant-addon/DOCS.md)

> ⚠️ **Настройте ровно один способ установки на один клиент.** Custom Component, приложение, Docker/PyPI и локальный stdio — это независимые способы запуска одного и того же сервера — выберите один и укажите вашему ИИ-клиенту единственный URL. Хранение двух записей для одного сервера в одном клиенте (например, локального входа `uvx ha-mcp@latest` с `HOMEASSISTANT_URL` / `HOMEASSISTANT_TOKEN` наряду с URL приложения или компонента) — известная причина зависаний подключения.

### Прочие способы установки

Эти способы запускают сервер вне Home Assistant — полезно для установок **Container** / **Core** (которые не могут запускать приложения) или для отдельного хоста. [Мастер настройки](https://homeassistant-ai.github.io/ha-mcp/setup/) генерирует точную конфигурацию для каждого клиента.

- **Docker (HTTP-сервер):** запустите `ghcr.io/homeassistant-ai/ha-mcp` в HTTP-режиме, указав URL вашего Home Assistant и долгоживущий токен (рекомендуется администраторский; токены не-администраторов работают с ограничениями), и подключите клиент к его секретному URL. См. [Мастер настройки](https://homeassistant-ai.github.io/ha-mcp/setup/) для полной команды и конфигураций под каждого клиента.
- **PyPI / uvx (HTTP-сервер):** запустите опубликованный пакет `ha-mcp` с помощью `uvx ha-mcp@latest` (или pip) как сервер streamable-HTTP тем же способом. Подробности в [Мастере настройки](https://homeassistant-ai.github.io/ha-mcp/setup/).
- **Локальный stdio (не рекомендуется):** запускает ha-mcp на вашей собственной машине через stdio. Одно-командные установщики в разделе **Демо-сервер** ниже используют этот путь; [Мастер настройки](https://homeassistant-ai.github.io/ha-mcp/setup/) описывает подключение к вашему Home Assistant.
- **Аутентификация OIDC:** ограничьте удалённый доступ внешним провайдером идентификации (Authentik, Keycloak, Auth0 и т. д.) вместо секретного URL — все аутентифицированные пользователи используют учётные данные сервера в Home Assistant. См. [Режим OIDC](docs/oidc.md).

  > ⚠️ **У stdio есть известные проблемы с транспортом.** Транспорт stdio имеет проблемы с подключением, которых нет у streamable HTTP ([#1713](https://github.com/homeassistant-ai/ha-mcp/issues/1713)). Он рекомендуется только для экспериментов/демонстраций и тестирования — для реальной настройки используйте Custom Component или любой HTTP-метод выше.

<details>
<summary><b>🌐 Удалённый доступ (Nabu Casa / Webhook Proxy app / OpenAI Tunnel)</b></summary>

> **Используете custom component HA-MCP?** Вам не нужен **Webhook Proxy** — у компонента есть собственный встроенный webhook для удалённого доступа (см. краткое руководство **Начало работы** вверху). Прокси предназначен для **приложения** (он также может обслуживать другой внешний сервер через свою опцию `mcp_server_url`). **OpenAI Tunnel** ниже отличается: он применим к **любому** способу установки, когда Home Assistant вообще не доступен публично (без Nabu Casa или обратного прокси).

Уже есть **Nabu Casa** или другой обратный прокси, направленный на ваш Home Assistant? Приложение Webhook Proxy пропускает MCP-трафик через вашу существующую настройку — без отдельного туннеля или проброса портов.

1. Установите **приложение MCP Server** (см. выше) и приложение **Webhook Proxy** из того же магазина
2. Запустите webhook proxy и **перезапустите Home Assistant**, когда появится запрос
3. Скопируйте webhook URL из журналов приложения:
   ```
   MCP Server URL (remote): https://xxxxx.ui.nabu.casa/api/webhook/mcp_xxxxxxxx
   ```
4. Настройте ваш ИИ-клиент с этим URL

Для других способов удалённого доступа (Cloudflare Tunnel, пользовательский обратный прокси) см. [Мастер настройки](https://homeassistant-ai.github.io/ha-mcp/setup/).

**ChatGPT / Codex за брандмауэром (OpenAI Tunnel).** Коннекторы ChatGPT обычно требуют публично доступный URL. Если вы не можете (или не хотите) его открывать, интеграция сообщества [OpenAI Tunnel for HA-MCP](https://github.com/norpol/hass-codex-tunnel-mcp) от [@norpol](https://github.com/norpol) запускает [`tunnel-client`](https://github.com/openai/tunnel-client) от OpenAI внутри Home Assistant и подключает ваш локальный MCP-сервер к туннелю, размещённому на OpenAI, через исходящее соединение — без проброса портов, обратного прокси или публичного URL. Направьте его на ваш ha-mcp URL, затем прикрепите коннектор ChatGPT к тому же идентификатору туннеля. См. [запись в FAQ](https://homeassistant-ai.github.io/ha-mcp/faq/#openai-tunnel) и [#1811](https://github.com/homeassistant-ai/ha-mcp/issues/1811).

[Документация Webhook proxy →](https://github.com/homeassistant-ai/ha-mcp/blob/master/homeassistant-addon-webhook-proxy/DOCS.md)

## 💬 Что с этим можно делать?

Просто общайтесь с Claude естественным образом. Вот несколько реальных примеров:

| Вы говорите | Что происходит |
|-------------|----------------|
| *"Создай автоматизацию, которая включает свет на крыльце на закате"* | Создаёт автоматизацию с правильными триггерами и действиями |
| *"Добавь карточку погоды на мою панель"* | Обновляет вашу панель Lovelace новой карточкой |
| *"Автоматизация с датчиком движения не работает, отлади её"* | Анализирует трассы выполнения, выявляет проблему, предлагает исправления |
| *"Сделай так, чтобы моя утренняя рутина также включала кофемашину"* | Читает существующую автоматизацию, добавляет новое действие, обновляет её |
| *"Создай скрипт, который включает режим кино: приглушает свет, закрывает жалюзи, включает телевизор"* | Создаёт переиспользуемый скрипт с последовательностью действий |

Меньше времени на настройку, больше времени на удовольствие от умного дома.

## ✨ Возможности

| Категория | Возможности |
|-----------|-------------|
| **🔍 Поиск** | Нечёткий поиск сущностей, глубокий поиск по конфигурации, обзор системы |
| **🏠 Управление** | Любой сервис, массовое управление устройствами, состояния в реальном времени |
| **🔧 Администрирование** | Автоматизации, скрипты, помощники, [панели](docs/dashboard-edits.md), зоны, области, группы, календари, blueprints |
| **📊 Мониторинг** | История, статистика, снимки камер, трассы автоматизаций, устройства ZHA |
| **💾 Система** | Резервное копирование/восстановление, обновления, приложения, реестр устройств |
| **🔒 Безопасность** | Режим «только чтение», включение/отключение по инструментам, политики безопасности инструментов (одобрение пользователем), автоматическое резервирование при редактировании |

Резервные копии редактирования шаблонных помощников (Template helper) сохраняют сохранённые опции через custom component HA-MCP, используя либо его запись Server, либо запись File & YAML Tools. Редактирование помощников, редактирование общих опций интеграций и удаление фиксируют стабильный идентификатор записи конфигурации и сопоставление идентификатора/имени сущности. Захват отказывается от деградированной очистки секретов. Восстановление существующего помощника требует свежей резервной копии безопасности, удаляет необязательные настройки, отсутствующие в снимке, и проверяет сохранённые опции.

Для перечисления и массового удаления резервных копий Template фильтруйте по идентификатору записи конфигурации, возвращаемому как `entity_id` при захвате. Захват принимает псевдоним сущности; фильтры истории используют стабильный идентификатор записи конфигурации. Воссоздание сообщает о заменяющем идентификаторе записи конфигурации и сохранённом сопоставлении сущностей отдельно.

Если исходная запись была удалена, восстановление воссоздаёт помощника и сообщает его новый идентификатор записи конфигурации. Сохранённый идентификатор сущности и пользовательское имя восстанавливаются, когда это доступно; занятый идентификатор сущности отклоняется до создания. Старые снимки без метаданных сущности не могут сохранить переименованные идентификаторы сущностей. Если после создания происходит коллизия или сбой проверки, новый помощник и исходная резервная копия сохраняются, а результат сообщает о новой записи для проверки. Прочие настройки реестра сущностей/устройств не восстанавливаются. Редактирование помощников и интеграций через один и тот же сервер ожидает завершения восстановления; другие клиенты Home Assistant находятся вне этой координации. ## 🆚 ha-mcp в сравнении со встроенным MCP Server в Home Assistant

Home Assistant поставляет собственную [интеграцию MCP Server](https://www.home-assistant.io/integrations/mcp_server/). Она построена на конвейере **Assist**, поэтому подключённый MCP-клиент может читать и управлять сущностями, которые вы открыли для Assist, и выполнять интенты, которые понимает Assist — удобно для голосового управления уже открытыми устройствами.

ha-mcp — это автономный сервер, созданный для **настройки, сборки и отладки** вашего умного дома, а не только для управления им. Помимо управления устройствами, он добавляет возможности, которых нет у встроенной интеграции:

| Возможность | Встроенный MCP Server | ha-mcp |
|-------------|:---------------------:|:------:|
| Управление открытыми устройствами, запрос состояний | Да | Да |
| Охват сущностей | Только сущности, открытые для Assist | Всё в Home Assistant |
| Создание / редактирование автоматизаций, скриптов, сцен | Нет | Да |
| Создание и редактирование панелей | Нет | Да |
| Отладка автоматизаций по трассам, чтение истории и журналов | Нет | Да |
| Управление помощниками, областями, зонами, метками, группами | Нет | Да |
| Резервные копии, приложения, HACS, реестр устройств и сущностей | Нет | Да |

**Правило большого пальца:** используйте встроенную интеграцию для голосового управления уже открытыми устройствами; используйте ha-mcp, когда хотите, чтобы ИИ-ассистент мог также собирать и поддерживать вашу конфигурацию Home Assistant.

## 🔌 Custom Component (ha_mcp_tools) — Файловые и YAML сервисы

Custom Component **HA-MCP** также предоставляет набор привилегированных инструментов, которые стандартные API Home Assistant обеспечить не могут: доступ к файловой системе и редактирование YAML-конфигурации. (Тот же компонент запускает полный сервер в процессе — это рекомендуемая установка из раздела **Начало работы** вверху.) Его запись **File & YAML services entry** (**HA-MCP File & YAML Tools**) включает инструменты ниже.

**Инструменты, требующие этот компонент:**

| Инструмент | Описание |
|------------|----------|
| `ha_config_set_yaml` *(бета)* | Безопасное добавление, замена или удаление ключей верхнего уровня YAML в `configuration.yaml` и файлах пакетов (автоматическое резервирование, проверка и проверка конфигурации) |
| `ha_list_files` *(бета)* | Список файлов в разрешённых каталогах |
| `ha_read_file` *(бета)* | Чтение файлов из разрешённых путей (YAML конфигурации, журналы и разрешённые каталоги) |
| `ha_write_file` *(бета)* | Запись файлов в разрешённые каталоги |
| `ha_delete_file` *(бета)* | Удаление файлов из разрешённых каталогов |

Резервное копирование и восстановление при редактировании шаблонных помощников (Template helper) также требуют этот компонент, используя либо запись Server, либо запись File & YAML Tools. Эти пять инструментов возвращают ошибку с инструкциями по установке, если компонент отсутствует.

Эти инструменты также требуют бета-флагов функций. См. **[Бета-функции](docs/beta.md)** о том, как их включить, — включая главный флаг `ENABLE_BETA_FEATURES`, который должен быть включён, прежде чем под-флаги файловой системы/YAML вступят в силу.

### Установка

Установите запись **HA-MCP File & YAML Tools** из того же **Custom Component HA-MCP**:

[![Откройте ваш экземпляр Home Assistant и откройте репозиторий в Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=homeassistant-ai&repository=ha-mcp-integration&category=integration)

Для добавления вручную: откройте **HACS** > **Интеграции** > меню с тремя точками > **Пользовательские репозитории** > добавьте `https://github.com/homeassistant-ai/ha-mcp-integration` (категория: Integration) > **Загрузить**. Или скопируйте `custom_components/ha_mcp_tools/` из этого репозитория в каталог HA `config/custom_components/`.

После установки перезапустите Home Assistant, затем откройте **Настройки** > **Устройства и службы** > **Добавить интеграцию**, найдите **HA-MCP Custom Component** и добавьте запись **HA-MCP File & YAML Tools**.

Чтобы запустить полный сервер ha-mcp в процессе через этот же компонент, см. раздел **Начало работы** вверху и [полную документацию по серверу в процессе →](docs/in-process-server.md).

## 🧠 Лучшие результаты с помощью Agent Skills

Этот сервер даёт вашему ИИ-агенту инструменты для управления Home Assistant. Для более качественных конфигураций объедините его с [Home Assistant Agent Skills](https://github.com/homeassistant-ai/skills) — предметными знаниями, которые учат агента лучшим практикам Home Assistant.

MCP-сервер может создавать автоматизации, помощников и панели, но у него нет мнения о том, *как* их структурировать. Без предметных знаний агенты склонны чрезмерно полагаться на шаблоны, выбирать не тот тип помощника или создавать автоматизации, которые сложно поддерживать. Навыки заполняют этот пробел: нативные конструкции вместо обходных путей через Jinja2, правильный выбор помощника, безопасные рабочие процессы рефакторинга и корректное использование режимов автоматизации.

### Встроенные навыки (Bundled Skills)

Навыки из `homeassistant-ai/skills` встроены и предоставляются как [MCP-ресурсы](https://modelcontextprotocol.io/docs/concepts/resources) через URI `skill://`. Любой MCP-клиент, поддерживающий ресурсы, может обнаружить их автоматически — ручная установка не требуется. Для клиентов, работающих только с инструментами (claude.ai и т. п.), навык лучших практик доступен через инструмент `ha_get_skill_guide`: вызовите его без аргументов, чтобы прочитать `SKILL.md`, или с параметром `file`, установленным на путь, на который ссылается `SKILL.md`, чтобы прочитать этот файл справки. Ресурсы не внедряются в контекст автоматически — клиенты должны явно их запрашивать, поэтому стоимость простоя контекста — это лишь перечисление метаданных.

`ha_get_skill_guide` — обязательный инструмент: каталог всегда его показывает (его нельзя отключить), чтобы клиенты, работающие только с инструментами, никогда не видели молча отсутствующей поверхности навыков.

Навыки всё ещё можно установить вручную для клиентов, предпочитающих локальные файлы навыков, — см. инструкции в [репозитории навыков](https://github.com/homeassistant-ai/skills).

## 🔍 Обнаружение инструментов для ИИ-агентов

По умолчанию полный каталог инструментов (~87) передаётся клиенту через стандартный ответ MCP `tools/list`. Клиенты с отложенной / по запросу загрузкой инструментов (claude.ai, Claude Desktop, Claude Code) отлично с этим справляются — инструменты подтягиваются в контекст только при необходимости, поэтому стоимость простоя контекста почти нулевая.

Для конфигураций *без* поддержки отложенной загрузки — таких моделей, как Claude Haiku, Gemini, совместимых с OpenAI локальных моделей и более мелких моделей с открытыми весами, или клиентов, которые внедряют все схемы инструментов независимо от модели (например, GitHub Copilot CLI), — предварительное перечисление всего каталога инструментов сильно увеличивает контекст простоя и может перегрузить малые модели. Для решения этой проблемы сервер поставляется с **режимом обнаружения на основе поиска**, построенным на основе BM25-преобразования поиска из FastMCP.

### Малые или локальные LLM (Ollama и т. п.)

Если ваша модель не видит инструменты или ваш Home Assistant, возможно, ей передают весь каталог инструментов сразу, и она с ним не справляется. Рекомендуется попробовать следующее:

- **Включите поиск инструментов** (`ENABLE_TOOL_SEARCH=true` или соответствующая опция приложения). Вместо предварительного перечисления каждого инструмента сервер прячет каталог за интерфейсом поиска, чтобы модель подтягивала только нужные инструменты, когда они ей нужны.
- **Увеличьте окно контекста модели выше значения по умолчанию.** Локальные среды поставляются с небольшими значениями по умолчанию (например, у Ollama `num_ctx`), которые не могут вместить большой набор инструментов плюс разговор — увеличьте его значительно сверх значения по умолчанию.

### Включение обнаружения на основе поиска

Установите ENABLE_TOOL_SEARCH=true (или переключите опцию в приложении HA). Полный каталог заменяется в списке инструментов четырьмя точками входа плюс небольшим набором всегда видимых «закреплённых» инструментов (ha_search, ha_get_overview, ha_report_issue и т. д.). Все инструменты остаются вызываемыми напрямую по имени после обнаружения:

| Инструмент | Назначение |
|------------|------------|
| `ha_search_tools` | Поиск по английским ключевым словам BM25 по всем инструментам, включая закреплённые. Скрытый инструмент возвращается компактно: имя, однострочное описание (первый абзац docstring), однострочный список `params` (типы, значения перечислений, обязательность) и прокси, который его выполняет. `ha_search_tools(tools=[...])` возвращает полное определение (описание, входную схему и аннотации) указанных инструментов — второй шаг перед вызовом. Закреплённый инструмент возвращает заглушку только с именем (`pinned: true`), указывающую обратно на список инструментов, и не занимает слот результата. |
| `ha_call_read_tool` | Выполняет инструмент с `readOnlyHint` по имени. Безопасно — клиенты могут автоодобрять. |
| `ha_call_write_tool` | Выполняет инструмент записи, который создаёт или обновляет данные. |
| `ha_call_delete_tool` | Выполняет инструмент, который удаляет данные. |

Разделение прокси позволяет MCP-клиентам применять разные политики разрешений для каждой категории (например, автоодобрение чтений, запрос на записи, подтверждение удалений) без разбора docstring инструментов.

Инструмент `ha_manage_*` сочетает несколько операций, поэтому он доступен через более чем один прокси: `ha_call_write_tool` и `ha_call_delete_tool` выполняют весь инструмент, тогда как `ha_call_read_tool` выполняет только те действия чтения, которые одобряет режим «только чтение» (тот же вердикт для каждого вызова), поэтому инструмент управления без одобренных действий чтения там недоступен. Результаты поиска перечисляют каждый прокси, через который можно получить доступ к инструменту. В режиме «только чтение» перечисляется только `ha_call_read_tool`; два других всё ещё отвечают клиенту, у которого есть их в кэшированном списке инструментов, и любая запись, которую они несут, получает ошибку режима «только чтение», а не `Unknown tool`.

| Настройка | По умолчанию | Описание |
|-----------|--------------|----------|
| `ENABLE_TOOL_SEARCH` | `false` | Заменяет полный каталог инструментов обнаружением на основе поиска (инструменты откладываются за поиском по запросу). |
| `TOOL_SEARCH_MAX_RESULTS` | `5` | Максимум скрытых инструментов, возвращаемых за один вызов `ha_search_tools` (диапазон 2–10); закреплённый инструмент, попавший в верхний предел, добавляется поверх него как заглушка только с именем. |
| `PINNED_TOOLS` | пусто | Разделённые запятыми имена инструментов, которые остаются всегда видимыми. Веб-интерфейс настроек — основной способ управления этим. |

### Когда включать

- **Claude Haiku, локальные модели, совместимые с OpenAI, Gemini или любая модель без нативной отложенной поддержки инструментов** — значительная экономия контекста простоя. То же относится к клиентам, которые внедряют все схемы инструментов независимо от модели (например, GitHub Copilot CLI, даже при запуске Claude Sonnet/Opus).
- MCP-клиенты, ограничивающие общее количество инструментов (некоторые ограничивают на уровне 100) — показывается минимальный набор (~10 инструментов) вместо 87.
- **Развёртывания, чувствительные к стоимости** — меньше неактивных токенов за ход.

Оставляйте его выключенным в клиентах с отложенной загрузкой инструментов (claude.ai, Claude Desktop, Claude Code); там полный каталог не имеет стоимости простоя, прямые вызовы пропускают шаг поиска, а встроенный поиск инструментов клиента — лучший выбор — нет смысла запускать поверх него поиск ha-mcp. Зависит ли откладывание инструментов, определяется комбинацией клиента и модели: одна и та же модель может вести себя по-разному в разных клиентах — GitHub Copilot CLI при запуске Claude Sonnet/Opus внедряет полный каталог и всё равно выигрывает от поиска инструментов здесь. Некоторые модели Codex и ChatGPT также включают отложенные инструменты — проверьте характеристики вашего клиента/модели напрямую, чтобы не оставлять эту функцию включённой без необходимости.

> 🔄 **Обновляйте список инструментов клиента после изменения этой (или любой другой) настройки.** Переключение `ENABLE_TOOL_SEARCH` (или изменение закреплённых/отключённых инструментов, режима «только чтение» и т. д.) меняет инструменты, которые показывает сервер, но ваш ИИ-клиент продолжает использовать **кэшированный** список инструментов, пока не перезапросит его. Перезапуск приложения или Home Assistant **не** обновляет клиент — переподключите или обновите MCP-сервер в клиенте (например, повторно добавьте/обновите коннектор в ChatGPT или закройте и снова откройте Claude Desktop). Если этого не сделать, вновь включённые инструменты вообще не появятся у клиента, а инструменты, которые сервер больше не показывает, всё ещё будут отображаться как доступные, но будут ошибаться при вызове (`Unknown tool` или ошибка режима «только чтение» для инструмента записи, который этот режим скрывает). ChatGPT иногда продолжает использовать устаревший список даже после удаления и повторного добавления коннектора под тем же именем — если инструменты всё ещё отсутствуют после повторного добавления, удалите коннектор и создайте новый с **другим именем**.

Для приложения HA та же опция задокументирована в [`homeassistant-addon/DOCS.md`](homeassistant-addon/DOCS.md#enable_tool_search) вместе с интерфейсом настроек в приложении для детального включения/отключения/закрепления инструментов.

### HTTP-соединения «только для чтения»

Добавьте `/readonly` к HTTP-конечной точке MCP сервера, чтобы ограничить это соединение
существующим режимом «только чтение», в то время как другие клиенты сохраняют обычный доступ:

```text
Обычный:      https://example.com/private_your_secret
Только чтение: https://example.com/private_your_secret/readonly
```

OAuth- и OIDC-соединения используют тот же вход/провайдера: например,
`https://example.com/mcp/readonly`. Никаких дополнительных секретов или серверов не требуется.
Соединения «только для чтения» скрывают инструменты записи и блокируют вызовы записи, включая вызовы
через кэшированные инструменты или прокси поиска. Глобальная настройка режима «только чтение» по-прежнему
ограничивает обе конечные точки при включении. Переподключите клиент после изменения его URL,
чтобы он обновил свой список инструментов.

Это режим соединения для автоматизированных агентов, а не отдельное разрешение для
учётных данных: те же учётные данные по-прежнему работают на обычной конечной точке. Webhook URL Home Assistant
также принимают суффикс:
`https://your-ha.example/api/webhook/<webhook-id>/readonly`. Это требует
обновлённой встроенной интеграции или dev-приложения Webhook Proxy (аддон) вместе с
обновлённым MCP-сервером.

## 🔒 Конфиденциальность

Ha-mcp работает **локально** на вашей машине. Данные вашего умного дома остаются в вашей сети.

- **Сегодня никакой телеметрии** — анонимная статистика использования запланирована как будущая функция (по состоянию на июнь 2026 г.); когда она появится, она будет следовать вашей настройке аналитики/телеметрии Home Assistant (которую можно переопределить), о чём будет объявлено в примечаниях к релизу и в веб-интерфейсе настроек не менее чем за месяц
- **Никакого сбора персональных данных** — мы никогда не собираем имена сущностей, конфигурации или данные устройств
- **Отчёты об ошибках под вашим контролем** — отправляются только с вашего явного согласия

Полные подробности см. в нашей [Политике конфиденциальности](PRIVACY.md).
